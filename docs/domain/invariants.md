# Invariants

Rules that must stay true. Each gets a test when its code is written; the "Enforced by" column then names the test.

| ID | Invariant | Enforced by |
|---|---|---|
| I1 | The instrumented app never fails, blocks or slows down measurably because of chepio-lens. SDK export is asynchronous with a bounded queue and drops spans on overflow or error. | Rust SDK: `sdk/rust/tests/unreachable_collector.rs` (collector not running, collector that never answers: every request under 50 ms, shutdown bounded); web SDK: `sdk/web/src/initLens.test.ts` "initLens with a broken collector" (the same two cases for `fetch`) |
| I2 | Payload values are redacted in the SDK before export and again by the collector on ingest, using the defaults in `../architecture/security.md`. Configuration can add keys, never remove defaults. | Rust: `conventions` `redaction::tests::shared_vectors_pass` (`conventions/testdata/redaction.json`); collector ingest pass: `services::redaction::tests::*`; TypeScript: `sdk/web/src/redaction.test.ts` (the same vectors), web SDK URL masking before export in `initLens.test.ts`; bodies and headers masked before export: Rust `sdk/rust/tests/payloads.rs`, web `sdk/web/src/payloads.test.ts` (demo login). Planned: demo login end-to-end test |
| I3 | A service node's id is `svc:<service.name>` (`unknown_service` when missing). Its kind is the resource's `lens.node.kind` when that is `frontend` or `service`; otherwise `frontend` when `telemetry.sdk.language = webjs`, else `service`. | `domain::span::tests::service_kind_follows_i3`, `domain::node::tests::service_node_id_follows_i3` |
| I4 | A database node's id is `db:<db.system.name>:<server.address>:<server.port>/<db.namespace>`, omitting missing parts. Every service using the same database points to one node. | `domain::node::tests::database_node_ids_follow_i4` |
| I5 | An external node's id is `ext:<server.address>:<server.port>`; `ext:<server.address>` without a port, `ext:unknown` without an address. Without `server.address` the host and port come from `url.full` (port by scheme). | `domain::node::tests::external_node_ids_follow_i5` |
| I6 | Edges come only from span data: a client span linked to a server span of another service gives an http edge; a client span with a database system gives a db edge; an unlinked client span gives an edge to an external node after the link window. | `domain::linker::tests::*` (client/server in both orders, database at once, external after the window, late server, same-service calls); with batches recorded from both SDKs: `tests/api.rs` `browser_and_api_batches_link_into_web_api_database_in_either_order`, `browser_calls_without_a_traced_backend_reach_an_external_node` |
| I7 | Linking gives the same graph whatever order the spans arrive in, within the link window. | `domain::graph::tests::every_arrival_order_gives_the_same_graph` (all 720 orders of a 6-span trace) |
| I8 | Collector domain code reads only normalized names; legacy semconv names are mapped once, at ingest. | `adapters::otlp::tests::json_with_legacy_names_is_normalized_once`; domain code imports only stable keys from `conventions::keys` |
| I9 | Every collector buffer, map and channel has a fixed bound; overflow drops the oldest entry and never blocks ingest. | Collector: `repositories::memory_store::tests::*`, `domain::graph::tests::node_and_edge_bounds_*`, `domain::linker::tests::*overflow*` and `order_queues_stay_bounded_*`, `adapters::sse::tests::a_lagging_subscriber_gets_resync`, `tests/api.rs` (413, 503, SSE client bound). Rust SDK export queue (2,048 spans) is filled past its bound in `sdk/rust/tests/unreachable_collector.rs`; web SDK queue in `sdk/web/src/initLens.test.ts` "drops spans beyond the export queue" |
| I10 | Payload and attribute values are never written to disk or to logs. | planned: log capture test on ingest of a payload with a marker string |
| I11 | The UI renders payload content as text, never as HTML. | planned: e2e test with an HTML/JS payload |
| I12 | Durations are computed within one span (one clock). Offsets between spans from different processes are shown as received, and a child that starts before its parent is flagged. Animation hops are placed along the call tree and never compare clocks of different processes. | Animation: `domain::request::tests::hops_follow_the_call_tree_whatever_the_clock_skew`. Planned: UI waterfall tests |
